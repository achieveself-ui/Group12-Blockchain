## 1. 摘要

### 1.1 项目做了什么

以简化模型复现 yETH 事件的三类教学缺陷（异常铸币 / 状态失同步 / 重复初始化），并给出修复版合约：固定 1:1 铸币规则的资产池（SecurePool），凭证为独立 ERC-20（PoolShareToken），仅池合约可 mint/burn；教学版（VulnerablePool）仅在 Hardhat 本地链运行，永不部署公共网络。

### 1.2 测了什么

- 正常业务路径：首次/连续存款、部分/全额赎回、多用户交叉（DR-01~07）；
- 拒绝能力：异常输入、越权、暂停状态机、重复初始化、凭证铸造权限、异常铸币防护（SEC-01~12）；
- 漏洞复现：同一攻击序列在漏洞版上触发三类缺陷（VUL-01~05）；
- 回归闸门：两版对照 + 固定种子不变量 INV1~INV5 + 极端边界 + 冒烟组（REG-01~04）。

### 1.3 结论（一句话）

> 【待补测：跑完全量后填写。参考句式："对本项目定义的攻击类别（异常铸币/状态失同步/重复初始化），SecurePool 的防护措施在 N 条用例与 M 组不变量序列下全部有效；结论仅限于本项目教学模型，不外推至真实协议。"】

## 2. 威胁模型

### 2.1 攻击者画像

持有**少量**测试资产的普通外部地址（非 owner、非池合约、无任何特权）。能调用的只有公开接口：`deposit` / `redeem` / `initialize` / 各查询函数，以及直接向池合约地址转账资产代币。

### 2.2 攻击目标

用远小于价值的成本换取**超额凭证**，再通过赎回抽走池内真实资产；即"投入 X，取回 Y，要求 Y >> X"。

### 2.3 攻击面清单

| 攻击面 | 威胁 | 防护期望 | 验证位置 |
|---|---|---|---|
| `deposit(assets)` | 零值/微额输入触发异常铸币；未授权扣款 | 零值拒绝；铸出恒等于存入 | SEC-01、SEC-12、REG-01、REG-03a |
| `redeem(shares)` | 超额赎回、池内不足时部分成功、max 级输入溢出 | 凭证不足/池内不足/零值一律回滚，无部分成功 | SEC-02~04、REG-03c |
| `initialize(...)` | 池清空后二次初始化改写关键状态 | 任意参数的第二次调用必回滚 | SEC-10、VUL-04、冒烟05 |
| PoolShareToken `mint/burn` | 绕开池子直接印凭证/销凭证 | 仅池合约可调，owner 直调也回滚 | SEC-11 |
| `pause/unpause` | 非 owner 操控状态机 | 仅 owner；暂停期写拒读通 | SEC-06~09、冒烟04 |
| 状态一致性（隐含） | 账面与真实余额失同步后被利用 | 三方恒等（账面=真实=供应量） | INV1/INV2、REG-01 终态行 |

### 2.4 明确不在威胁模型内

闪电贷组合攻击、真实 StableSwap 定价曲线操纵、跨池组合、MEV、私钥管理——见第 7 节残余风险。

## 7. 残余风险与限制（如实声明）

1. **未做形式化验证**：不变量靠固定种子随机序列抽查（10 组 × 12 步），不是数学证明；
2. **未模拟真实 StableSwap 算法**：本项目是 1:1 教学模型，结论不外推到真实 Yearn/Curve 合约；
3. **未覆盖闪电贷组合攻击**：单池单资产模型内不存在该攻击面，但真实协议中这是主要向量；
4. **"不安全的减法"仅形式对应**：0.8+ checked arithmetic 使真下溢不可复现（见第 3 节末）；
5. **静态分析深度有限**：Slither 为模式匹配工具，存在误报/漏报；【若 5.0 勾了"不可用"】本次分析以编译警告 + 人工检查替代，深度低于工具链；
6. **测试覆盖率的盲区**：未覆盖行/分支将在覆盖率报告审阅时逐条注明原因（教学版故意保留的分支单独标注）；
7. **环境假设**：所有结论基于 Hardhat 本地链（chainId 31337），未在 Sepolia 上做完整回归（部署验证属另一工作项）。
