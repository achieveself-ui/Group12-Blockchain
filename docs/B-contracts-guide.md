# B 合约实现说明

这是课程局部教学实现，不是金融产品、安全审计或真实事件完整复现。固定五项功能中的合约基础及本地对比由 B 支持；前端、正式测试安全报告及部署分别由 D、C、E 完成。

## 正式合约与状态

| 合约 | 状态 | 权限与用途 |
|---|---|---|
| TestToken | OZ ERC20 余额、授权、供应；Ownable owner | 仅 owner mint；不含扣款后门，无初始供应 |
| PoolShareToken | OZ ERC20 状态；immutable pool | 仅池 mint/burn；普通用户可转账；没有管理员 |
| SecurePool | assetToken、shareToken、initialized；继承 owner、paused、重入状态 | owner 一次初始化、暂停/恢复；用户固定 1:1 存赎 |
| VulnerablePool | 上述类似状态，加 cachedPoolBalance | 故意保留教学缺陷；31337 链限制 |

构造参数、事件及逐项错误见 [接口草案](api-spec-draft-B.md)。没有代理或升级功能，没有救援取款、收益、费用、兑换价格、闪电贷或额外核心业务。

## 安全池流程与信任边界

初始化由部署者 owner 执行，仅成功一次；失败交易不消耗初始化机会。检查代码、代币不同、凭证绑定、供应为零、18 decimals。管理员必须使用本项目编译出来的 PoolShareToken 和 TestToken；仅凭接口响应不能证明陌生合约可信。

存款：检查初始化、未暂停、重入锁、非零数量、现有背书；SafeERC20 转入；验证池余额增加量和用户减少量均等于 assets；铸等量凭证，再检查背书，发 Deposited。转入发生在铸造之前，外部调用阶段由 nonReentrant 保护，失败整笔回滚。

赎回：检查初始化、暂停、非零数量、用户凭证、实际资产及全局背书；先 burn 再 SafeERC20 转出；验证池减少量和用户增加量，检查剩余背书，发 Redeemed。任何后续失败都撤销 burn 与资产变化。

支持资产限定为本项目的普通、18 位、无转账费用、无重基、无黑名单、无额外扣款行为的 TestToken。余额差检查额外拒绝明显的手续费/异常转移，但不承诺支持任意恶意 ERC20，更无法防止外部资产以后自行改余额或撒谎。测试异常资产只位于 contracts/dev，不属于正式资产或部署清单。

不变量：`poolAssets >= totalSupply`；成功存赎时资产与凭证供应变化量相等。捐赠使左侧更大，不影响 1:1。所有凭证赎回后，捐赠留在池中，没有管理员提取接口。凭证可转移，持有者可赎回；丢失凭证或直接转给池的凭证无救援机制。暂停不阻止代币自身转账和捐赠。

## 原测试计划的数学问题

计划只给出首次 shares=assets，后续 shares=assets*TS/CB，赎回 assets=shares*CB/TS。清池后 TS=0、CB=D>0：若直接使用比例公式，16*0/D=0；若 TS=0 走首次分支，受害者存入 V 得 V 凭证，缓存残留 D 加 V，则攻击者只得到 floor(16*V/(D+V))，不超过16。若缓存更新为真实 V，则恰为16。单凭残留不能推出 2.35×10^23。

计划同时混用“10,000 token”和 TS=10,016 等最小单位数字。本演示统一使用整数最小单位，不把10,000解释为10,000×10^18。原资料声称“与 B 约定”并未得到当前用户确认。

## 本次教学决定（待 A/C 同步）

使用两个明确错误产生异常铸币：赎回忘记减少缓存；后续有供应且缓存大于实际资产时，错误执行 `unchecked { shares = assets - cachedPoolBalance; }`。这不是合理定价公式，故意用来展示错误状态叠加不安全减法的影响。初始/清空后的 TS=0 分支仍按 1:1 铸币，但把新资产加到残留缓存。

赎回统一采用 `Math.mulDiv(shares, actualAssets, totalSupply)`，向下取整，以真实池内资产为上限；不是计划中基于缓存的赎回公式。使用 mulDiv 是为了避免异常大凭证在中间乘法溢出导致演示无法观察资产损失，并非用测试修改结果。

序列（所有单位为最小单位）：

1. 攻击者存1000，得到1000凭证；全部赎回，实际资产和供应归零，缓存残留1000。
2. 受害者存10000，得到10000凭证，实际余额10000，缓存11000。
3. 攻击者存16，错误减法产生 `M = 2^256 - 10984` 凭证；总供应 `M+10000 = 2^256-984`，没有触发 ERC20 供应溢出。
4. 攻击者赎回全部 M，取得 `floor(M*10016/(M+10000)) = 10015`；相对存16净获利9999，池留1。
5. 受害者赎回10000，只取得1，损失9999。

不需要测试改存储、管理员异常 mint 或硬编码目标铸币数。任何赎回造成缓存大于实际余额后都可能形成触发条件，并不只限于清池；16没有神奇含义。部分输入会因剩余安全算术溢出而回滚，不能声称任意输入都可“无限铸币”。

安全版使用完全相同的存款金额和顺序；最后按“赎回各自全部持有凭证”进行等价操作，因此攻击者的最后赎回参数是16而不是 M。安全池只铸16、只还16、攻击者收益0、受害者损失0。若向安全池直接传 M，因凭证不足回滚。

另一个独立教学缺陷：VulnerablePool 初始化没有权限和一次性检查，陌生用户可以替换资产参数、重置缓存，使旧资产与凭证脱节。安全池 owner 检查与永久 initialized 标记阻断此操作。清池不应意味着重新初始化。
