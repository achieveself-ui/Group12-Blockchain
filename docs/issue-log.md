**严重度定义**：
- **P0 阻断**：主链路失效或资金安全直接受损（异常铸币、资产可被抽走、正常存赎失败）；
- **P1 严重**：防护机制失效但需特定触发条件（越权、暂停失效、二次初始化成功）；
- **P2 一般**：不危及资产的正确性问题（事件字段错误、查询口径不一致、覆盖率不达标）。

### ISSUE-001 修复版在清空池子后微额存款仍铸出超额凭证

- 发现日期：2026-11-18
- 严重度：**P0 阻断**
- 关联场景 ID：SEC-12 / REG-01（S3 微额存款步）
- 关联测试：test/secure-pool.test.js → "SEC-12 漏洞版输入重放：清空池后微额存款"；test/security-regression.test.js → "同一组输入：正常存款两版一致，漏洞版复现缺陷，修复版拒绝或 1:1"
- 发现时 commit：`4c5d6e7`
- 最小复现命令：
      npx hardhat test test/security-regression.test.js --grep "同一组输入"
- 期望行为：清空池子（受害者全额赎回）后，攻击者 deposit(16) 应当被回滚，或铸出的凭证严格等于 16（1:1）。
- 实际行为：交易成功，攻击者凭证余额从 0 变为 235000000000000000000016（约 2.35×10²³），日志关键行：

      S3 微额存款 16 | 漏洞版：成功，铸 235000000000000000000016 | 修复版：成功，铸 235000000000000000000016
      AssertionError: 修复版微额存款出现超额铸币：异常铸币防护失效

  修复版与漏洞版铸币量完全相同，说明防护代码未生效（疑似 `totalSupply == 0` 分支仍沿用了残留余额做分母）。
- 影响范围：异常铸币防护整体失效，攻击者可凭 16 wei 级成本抽干池内全部资产；**阻断验收**（防护矩阵第 10 行）。
- 状态：closed
- 责任人：B
- 关闭条件：SEC-12 与 REG-01 定向通过 + 全量回归通过
- 关闭日期：2026-11-20（修复 commit `a1b2c3d`，全量 31/0，见 regression-log 当日行）
- 验证人：C

### ISSUE-002 非 owner 调用 pause() 成功，权限校验缺失

- 发现日期：2026-11-18
- 严重度：**P1 严重**
- 关联场景 ID：SEC-06
- 关联测试：test/secure-pool.test.js → "SEC-06 非 owner 调 pause() 必须回滚"
- 发现时 commit：`4c5d6e7`
- 最小复现命令：
      npx hardhat test test/secure-pool.test.js --grep "SEC-06"
- 期望行为：非 owner 账户（alice）调用 `pause()` 必须回滚，且 `paused()` 保持 false。
- 实际行为：alice 调用 `pause()` 交易成功，`paused()` 返回 true，并发出 `Paused(alice)` 事件。日志关键行：

      AssertionError: 期望回滚但交易成功：pause() 疑似缺失 onlyOwner 校验
      paused() 期望值 false，实际 true

  任意地址可暂停池子 → 拒绝服务向量（任何人都可冻结全部用户的存赎）。
- 影响范围：可用性防护失效；不直接损失资产，但违背权限模型；影响防护矩阵第 6 行。
- 状态：closed
- 责任人：B
- 关闭条件：SEC-06 定向通过 + 冒烟04 通过 + 全量回归通过
- 关闭日期：2026-11-19（修复 commit `9f8e7d6`，见 regression-log 当日行）
- 验证人：C
